# EXSET-016 plan review — 2026-10-15

**Reviewer:** plan-reviewer. **Verdict:** DECISION NEEDED — on a trimmed client, a public-setter `IFactorySaveMeta` class that gets no generated ordinal converter (its constructor takes a service, or the class is not `partial`, or it is nested) loses `IsNew`/`IsDeleted` in both formats unless client code reads them. This was measured. Should 016 fix it in the generator, or should the page document the condition and a bug be filed?

There is no other veto-tier finding.

Pass B reality check:
- **The experiment is sound for what it measures.**
  - **`IsTrimmable` reached every project, which is harmless here.** `016-trim-partial-trimmable-publish.log` shows NETSDK1212 from `Generator.csproj`, so the property was passed globally and flowed into every project. `RemoteFactory.csproj:12` already sets `IsTrimmable`, so the only material change was the harness assembly. That is equivalent to the page's Step 1 on a domain project.
  - **The console harness stands in for a Blazor client on the points that matter.** Under `partial`, an assembly is trimmed or copied on the `IsTrimmable` assembly metadata (`Microsoft.NET.ILLink.targets:24-27`, ILLink.Tasks 9.0.16). That holds whether the domain is the entry assembly, as in the harness (rooted `RootMode="EntryPoint"`, `:274`), or a referenced one, as in Blazor.
  - **The JSON reflection switch differs, and does not matter.** A trimmed console defaults `JsonSerializerIsReflectionEnabledByDefault` to false (`ILLink.targets:50`), and Blazor sets it true (`BlazorWebAssembly.Current.targets:22`). It is irrelevant, because `NeatooJsonSerializer` sets its own resolver (`NeatooJsonSerializer.cs:74`).
  - **What the harness cannot model.** A Blazor app can carry a non-trimmable third-party assembly that references domain types and roots them under `partial`. That case is Theoretical.
- **What the current IFactorySaveMeta section claims** (`trimming.md:438-510`):
  - Under trimming, the trimmer "narrows the property itself from `public` to `private`" when only interface dispatch reads the getter.
  - `[DynamicallyAccessedMembers]` "does not prevent visibility narrowing", and `[DynamicDependency]` on the constructor is the fix.
  - Public setters "avoid both" requirements at the cost of encapsulation.
  - Person still carries that recipe and its comments (`PersonModel.cs:32-46, 68-72`).
- **What is actually true:**
  - **ILLink does not narrow visibility.** It removes accessors that nothing reaches.
  - **The "private" output is a leftover setter.** Take `get; private set;` with the getter removed: only the private setter remains, and ILSpy then renders the property as `private`. That is the old section's observation.
  - **Public setters have the same exposure.** In the probe below, a public `get; set;` decompiles as `{ set; }` with its getter gone.
  - **A read through `IFactorySaveMeta` does root the getter** (measured), contrary to the old text.
  - **Private setters fail in Ordinal with no trimming involved.** In the Ordinal format, a private-setter property is never serialized at all. The converter takes only public, internal or init setters (`FactoryGenerator.Types.cs:440-446, 506-518`).
- **The mechanism that roots `IsNew`/`IsDeleted` today is the generated per-type ordinal converter.** Nothing else roots them.
  - **Two members reference the accessors.** `{T}OrdinalConverter.Write` reads each ordinal property's getter, and `Read` sets each through an object initializer (`TrimSaveTarget.Ordinal.g.cs:38-44, 47-64`). `ToOrdinalArray` also reads the getters.
  - **The registration is unconditional, so it covers both formats.** `FactoryServiceRegistrar` registers the converter through `NeatooOrdinalConverterFactory.RegisterConverter` (`TrimSaveTargetFactory.g.cs:553`) without checking the format. The Named format never uses the converter, but the accessors it references survive for the reflection serializer.
  - **Nothing else reaches them on a client.** The only other reads are in `LocalSaveCore` (`:381-400`), and that is behind the guard and trimmed. The library itself never reads `IsNew` or `IsDeleted` (no match under `src/RemoteFactory`). The DI registration `AddTransient<T>` keeps constructors only.
  - **The converter is emitted only when all of these hold** (`FactoryModelBuilder.cs:308-313`): the class is `partial`, is not nested, is not a collection, has an accessible ordinal property, and does not require service instantiation. Callout 1 depends on this.
  - I published the harness with `full` and decompiled it: `TrimSaveTarget` keeps `IsNew { get; set; }` and `IsDeleted { get; set; }`, and its `[Remote]` bodies are gone.
- **The probe** was a scratch console outside the repo, with the harness's trim settings (`full`, `IsServerRuntime=false` with `Trim="true"`) and project references to `RemoteFactory` and `Generator`.
  - It holds two public-setter `IFactorySaveMeta` classes: `PlainMeta` (`partial`, parameterless) and `CtorServiceMeta` (`partial`, constructor `[Service] IStamp`). Each is set to `Id = 7, IsNew = false, IsDeleted = true` and serialized through the client container's `INeatooJsonSerializer`, in Ordinal and in Named. No getter is read anywhere in the program.
  - **Untrimmed,** both classes write all three values in both formats.
  - **Trimmed,** `PlainMeta` writes `[7,true,false]` and `{"$id":"1","Id":7,"IsNew":false,"IsDeleted":true}`. `CtorServiceMeta` writes `{}` in **both** formats, and ILSpy shows `public bool IsNew { set; }`.
  - **A server would rebuild that `{}` with the initializer's `IsNew = true`, so the Save becomes an Insert.**
  - **One read changes the outcome.** Adding a single `IFactorySaveMeta asMeta = svc; asMeta.IsNew` read brought `"IsNew":false` back, while `IsDeleted` stayed dropped. On that object a Delete would arrive as an Update.
- **T-27, RemoteFactory's own converters:**
  - `NeatooOrdinalConverterFactory` and `NeatooOrdinalConverter<T>`, plus each generated `{T}OrdinalConverter`. These are added only in the Ordinal format (`NeatooJsonSerializer.cs:81-84`).
  - `NeatooJsonConverterFactory`. This is an abstract, public extension point (`NeatooJsonConverterFactory.cs:10`), resolved from DI (`NeatooJsonSerializer.cs:88-91`). Its one built-in implementation is `NeatooInterfaceJsonConverterFactory` with `NeatooInterfaceJsonTypeConverter<T>`, which writes `$type`/`$value` (`AddRemoteFactoryServices.cs:113-115`).
  - `RecordBypassConverterFactory` and `RecordBypassConverter<T>` (internal).
  - `LazyLoadJsonConverterFactory` (internal). It is excluded under R-K, so the page should not name it.
  - Reference handling is not a converter: it is `NeatooPreserveReferenceHandler` with `NeatooReferenceResolver`.
  - **The external names.** `NeatooBaseJsonTypeConverter`, `NeatooListBaseJsonTypeConverter`, `IEditBase`, `IValidateBase` and `IEditListBase` exist nowhere in RF code. A comment in `SharedReferenceTests.cs:160` is the only mention. An external framework plugs in by registering `NeatooJsonConverterFactory` services.
- **The LazyLoad removal is clean.** Nothing outside the two pages references `LazyLoadSamples.cs`'s types or its two regions, and no page links to `lazyload.md` except a release note (callout 8).
- **Size.** The plan is 131 lines long, with 5 steps and 5 Acceptance bullets. It is one deliverable.
