Constraints on the constructor's shape are in callout 2.
- **The Save name and its nullability.** A method `Upsert` with `[Insert, Update]` gives two write models in one group. The name is `Save` + the postfix of the group's highest operation (`FactoryModelBuilder.cs:680-683`; Delete 16 > Update 8 > Insert 4, `AuthorizeFactoryOperation.cs:12-14`). It is the default save, so `IFactorySave<CustomerPreferences>` is implemented and routes to it (`ClassFactoryRenderer.cs:164-166, 1238-1256`). Callout 7 covers what changes when a Delete joins.
- **Static commands through `IOrderFactory` on the server work.** `Order.OpenDraft` already resolves `IOrderFactory` as a `[Service]` and calls `FetchDraft` and `Create` on the server (`Order.cs:342-349`, `OrderFactory.g.cs:502-506`). The server's factory is the local one, so `Fetch` and `Save` go to `LocalFetch` and `LocalSave`. `IsServerRuntime` defaults to true in the test process (`NeatooRuntime.cs:12-14`). Nested entry calls are safe: `FactoryEntryCall` drains only at the outermost call (`FactoryEntryCall.cs:28-49`). Since #113, a plain-`Task` `[Execute]` compiles (`AllPatterns.cs` `_Notify`). Static `[Execute]` is invoked by position: values, then services, then the token (`StaticFactoryRenderer.cs:304-321`). The plan's commands follow that order. How a server exception surfaces is callout 6.
- **Order's start hook runs for Insert and Update.** `FactoryStartAsync` runs before `cTarget.Insert` and `cTarget.Update` (`OrderFactory.g.cs:215-218, :286-289`). Insert and Update call `MapTo` after it (`Order.cs:265, :282`), so a normalization made in the hook reaches the row. The hook also runs for Fetch, FetchDraft and Delete (`OrderFactory.g.cs:137-140, :432-435, :356-359`). It does not run for `Order.Create`, which is synchronous and is checked only against `IFactoryOnStart` (`:77-81`).

The five deletion files define only these regions, plus the orphan `operations-params-array-batch`. Nothing else in the reference app uses their types: the two `TransferResult` and `EmployeeTransferCommand` hits are separate types in other namespaces. No page outside the scope embeds a region being deleted. Design has no nested region today. The nesting proof is EXSET-005's probe (`plans/005-readme-getting-started.md:244`). `readme-domain-model` is embedded at `README.md:59`, `getting-started.md:131` and `the-problem.md:44`.
