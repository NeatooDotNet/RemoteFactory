# v1.10.9 — An Authorization Refusal Reaches the Client Over HTTP

**Released:** 2026-10-16
**Breaking changes:** No. Update client and server.

## Overview

One fix, across both packages. A refusal from `[AuthorizeFactory<T>]` on an interface-factory method or a static `[Execute]` is thrown on the server as `NotAuthorizedException`. Over HTTP it escaped `UseNeatoo()`'s endpoint as a 500, so the client threw `HttpRequestException`, and the exception type, its message and its `Context` were lost (#103). The client now gets the same `NotAuthorizedException` the server threw.

## Bug Fixes

### An authorization refusal over HTTP arrived as a 500 (#103)

A class factory carries a refusal back in `Authorized<T>`. An interface-factory method and a static `[Execute]` are delegates with no `Authorized<T>` to carry it, so their checks throw `NotAuthorizedException` on the server. In the in-process test containers that exception reached the caller. Over HTTP the endpoint ended the request as a 500 and logged it as a failed request at Error. The client's call threw `HttpRequestException`, so code that caught `NotAuthorizedException` never ran.

The endpoint now answers the refusal itself:

| | Before | Now |
|---|---|---|
| The server | 500, logged as `RemoteRequestFailed` at Error | 403 with a body carrying `Message`, `Context` and `Authorized`, marked by the `X-Neatoo-Not-Authorized` header; logged at Warning (event 7009) |
| The client | `HttpRequestException`, `StatusCode` 500 | `NotAuthorizedException` with the server's `Message`, `Context` and `Authorized`; logged at Information (event 3013) instead of `RemoteCallError` at Error |

This covers any `NotAuthorizedException` thrown by a `[Remote]` operation: interface-factory methods, static `[Execute]`, and the operation's own code. A 403 without the header, such as an authentication scheme's forbid, still throws `HttpRequestException`.

Exposed: any client that calls an interface factory or a static `[Execute]` under `[AuthorizeFactory<T>]` over HTTP, and any alerting that read those refusals as server errors.

## What's New

Nothing new for application code. Two log events are added: 7009 on the server and 3013 on the client.

## Migration Guide

- **Update client and server.** The server half is in `Neatoo.RemoteFactory.AspNetCore` and the client half in `Neatoo.RemoteFactory`. No rebuild of domain assemblies is needed.
- **Mixed versions fail loudly, never silently.**
  - An old client talking to a new server gets `HttpRequestException` with `StatusCode` 403 instead of 500.
  - A new client talking to an old server still gets the 500.
- **Code that read `HttpRequestException` 500 as "refused"** now receives `NotAuthorizedException`; catch that instead.

## Testing

- **`EndpointAuthorizationTests`** (7 tests) hosts `UseNeatoo()` in Production on TestServer. It covers:
  - a bool refusal and a string refusal;
  - a `Task` method;
  - a static `[Execute]`;
  - the log levels on both tiers;
  - a foreign 403 that still throws `HttpRequestException`;
  - an allowed call.

  Without the fix, the five refusal tests fail with `HttpRequestException` (500).
- **The Design test** `AuthorizeFactoryHttpTests.InterfaceFactory_RefusedCall_ThrowsNotAuthorized_WithTheServersContext` covers `ICustomerDirectory` over `DesignHttpHost`. It fails without the fix.
- **`Neatoo.RemoteFactory.sln`:** 871 unit tests and 664 integration tests pass (5 skipped, all pre-existing), on net9.0 and net10.0.
- **`Design.sln`:** 176 tests pass on both (1 skipped as a known bug).
