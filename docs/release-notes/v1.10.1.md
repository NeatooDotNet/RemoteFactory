# v1.10.1 — Dictionary Entries and Public Fields Survive Trimming

**Released:** Not yet — set this line when the `v1.10.1` tag is pushed. Publish v1.10.0 first: its tag exists but has not been pushed, so v1.10.0 is not on NuGet.
**Breaking changes:** No. Trimmed clients now preserve types they used to drop, so a published bundle can grow by the size of those types.

## Overview

The generator's DTO walk decides which types a publish-trimmed client keeps. It missed two shapes: the key and value types of a dictionary, and types reachable only through a public field. A type reachable only that way was trimmed, and the client failed to deserialize it. Both shapes are now walked, along with the element of a collection nested inside another collection, and a consumer's own generic collection types.

## Bug Fixes

### Dictionary keys and values are preserved

The walk unwrapped a collection through its one `IEnumerable<T>` argument. A dictionary enumerates `KeyValuePair<TKey, TValue>`, which is a `System` type the walk rejects, so neither the key nor the value type was ever visited. A DTO reachable only as a dictionary value — a `Dictionary<string, LocationDto>` on an entity, in a factory signature, or on an event record — got no preservation and failed on the client:

```
NotSupportedException: Deserialization of types without a parameterless constructor, a singular
parameterized constructor, or a parameterized constructor annotated with 'JsonConstructorAttribute'
is not supported. Type 'YourApp.LocationDto'. Path: $.someKey
```

Blazor WebAssembly reports the same failure as `DeserializeNoConstructor, JsonConstructorAttribute, YourApp.LocationDto`, because it uses resource keys. Both halves of every generic dictionary are now walked: `Dictionary`, `IDictionary`, `IReadOnlyDictionary`, and the sorted, concurrent, immutable, and custom generic dictionaries.

**Why this surfaced only after v1.7.0.** Before v1.7.0, async `[Remote]` bodies shipped to trimmed clients, and a `new LocationDto()` inside one kept the constructor alive by accident. v1.7.0 stopped shipping those bodies, which was correct, and that exposed the gap. A consumer upgrading from v1.5.0 found it in a published build. The [v1.7.0 Migration Guide](v1.7.0.md#migration-guide) now carries this upgrade hazard.

### Types reachable through public fields are preserved

`NeatooJsonSerializer` runs with `IncludeFields = true`, so public fields are on the wire, but the walk visited properties only. Public instance fields are now walked alongside properties on DTOs, event records, and `[Factory]` entities. An entity's public fields cross the wire in `Named` format, and always for an entity whose constructor takes required parameters; only the default ordinal path carries properties alone.

### Nested collections reach their elements

`List<List<T>>` and `Dictionary<string, List<T>>` unwrapped one level and stopped at a `System` collection, so `T` was never reached. Unwrapping is now recursive.

A collection type of your own, such as `PagedList<T> : List<T>`, is now preserved together with its element, because the serializer constructs both. Before this release a nested one kept the collection and lost the element, and a top-level one kept the element and lost the collection.

## What's New

None. No public API changed.

## Behaviour Notes

- **More types are preserved.** Every newly reached DTO gets a `Register<T>` or `PreserveType<T>` call in a generated registrar, so a trimmed bundle can grow by the size of those types. That is the fix.
- **Unwrapping terminates by construction.** A self-referential enumerable such as `Node<T> : IEnumerable<Node<T>>` keeps its previous registration. A type whose enumeration expands without repeating stops at a depth cap of 8 instead of overflowing the generator's stack, which would otherwise have removed every factory from the build.

## What this release does not claim

Some shapes remain out of the walk's reach. A DTO reachable only through one of them still needs a `LinkerConfig.xml` entry or a `DtoConstructorRegistry` call in client DI setup:

- a member typed as an interface or abstract class whose concrete type is a plain DTO, because the `$type` discriminator picks it at runtime;
- a tuple element;
- the element of a non-generic collection subclass, such as `class Locations : List<LocationDto>`;
- an `object` value;
- a DTO that reaches the client only through your own HTTP or JSON code.

[IL Trimming: What the walk does not reach](../trimming.md#what-the-walk-does-not-reach) lists them with both remedies.

## Migration Guide

**None required.** Update the package and rebuild. The generator emits the preservation into your own assemblies, so the rebuild is what picks it up.

Once rebuilt, you may be able to delete `LinkerConfig.xml` entries for DTOs reachable only through dictionary entries or public fields. Publish `Release` and smoke-test before relying on that.

## Testing

- **Trimmed harness.** Two consumer-shaped checks run in the publish-trimmed CI harness: a dictionary value whose only construction site is an async `[Remote]` body, and a DTO reachable only through a public field. Both were observed **red** on the trimmed client before the fix, with the exact exception the consumer hit, and green untrimmed in the same session, so trimming caused the red. Both are green after the fix.
- **Generator tests.** 23 discovery tests per framework cover each shape through each discovery entry point — factory signatures, entity members, and event records — plus both preservation buckets, dictionary keys, nullable values, consumer collections, and the safety cases. The shape tests were observed red against the unchanged generator. The depth-cap test's negative control overflowed the stack with the cap lifted.
