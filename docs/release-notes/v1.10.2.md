# v1.10.2 — A Static `[Execute]` Can Return `Task`

**Released:** 2026-10-10
**Breaking changes:** No.

## Overview

A static `[Execute]` declared as returning non-generic `Task` generated code that did not compile. NF0102 has always accepted that return ("must return Task or Task&lt;T&gt;"), so the method passed every rule and then failed inside the generated file. It now generates a `Task` delegate and round-trips with no result, which is the natural shape for a command that has nothing to report.

## Bug Fixes

### `[Execute]` returning `Task` compiles and runs (#113)

The static factory renderer wrapped the method's return type in `Task<>` unconditionally. For a method returning `Task<T>` the model holds `T`, which is right. For a method returning `Task` the model holds `Task` itself, so the generated delegate was declared `Task<global::System.Threading.Tasks.Task>` and the consumer's build failed in their own `obj/` folder:

```
error CS0266: Cannot implicitly convert type 'System.Threading.Tasks.Task' to
'System.Threading.Tasks.Task<System.Threading.Tasks.Task>'. An explicit conversion exists
error CS1662: Cannot convert lambda expression to intended delegate type because some of the
return types in the block are not implicitly convertible to the delegate return type
```

The error pointed at generated code, not at the method, and no NF diagnostic named the cause. The existing NF0102 test pinned that no NF diagnostic fires for a `Task` return, but it never compiled the generator's output, so nothing caught the failure.

A `Task`-returning `[Execute]` now generates:

```csharp
public delegate Task Notify(string recipient, string message, CancellationToken cancellationToken = default);
```

With `[Remote]`, the client awaits until the server method has completed, a server exception rethrows at the await, the relay batch is delivered, and no result is read. Without `[Remote]`, it runs on the calling tier, as every bare `[Execute]` does since v1.9.0. The server side needed no change: it already serialized no result for a non-generic `Task`.

The skill and the Design reference previously taught the opposite rule ("`[Execute]` must return `Task<T>`, not `Task`") and recommended a `Task<bool>` that always returned `true`. Both now say: `Task` when there is no result, `Task<T>` when the caller needs one, never `void` (NF0102).

## What's New

Nothing new in the public API. One member was added in the `Neatoo.RemoteFactory.Internal` namespace, which carries no compatibility guarantee: `IMakeRemoteDelegateRequest.ForDelegateNoResult`, the call the generated client registration makes for a `Task`-returning `[Remote, Execute]`. It is a default interface member that forwards to `ForDelegateEvent`. A custom `IMakeRemoteDelegateRequest`, such as a test stand-in, keeps compiling, and it handles the new call through its existing `ForDelegateEvent`.

## Behaviour Notes

- **Generated code shape.** A `Task`-returning static `[Execute]` now produces a `Task` delegate type. Before this release that shape did not compile, so no working consumer code changes.
- **Class-level `[Execute]` is unchanged.** It must still return `Task<T>` of the containing type. A class-level `[Execute]` returning plain `Task` still fails in generated code (anti-pattern #9 in the skill). A diagnostic for it is planned.

## Migration Guide

**None required.** Update the package and rebuild. If you wrote `Task<bool>` commands that always return `true` only because `Task` did not work, you may change them to `Task`. Client and server must update together, as for any change to a delegate's signature.

## Testing

- Generator: the output for `[Remote]` and bare `Task`-returning `[Execute]` is compiled in-test. These tests failed before the fix with CS0266/CS1662.
- Integration, on the serializing client/server container pair: the call crosses and runs with the server's service; an async body completes before the await returns; a server exception reaches the client; the bare form stays local.
- Design: `ExampleCommands.Notify` is sent from the client and observed on the server.
- `Neatoo.RemoteFactory.sln`: 829 unit and 632 integration tests pass (5 skipped, all pre-existing), on net9.0 and net10.0. `Design.sln`: 104 tests pass on both.
