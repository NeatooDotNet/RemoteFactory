# v1.10.3 — A `partial` `[Factory]` List Keeps Its Items

**Released:** 2026-10-12
**Breaking changes:** No.

## Overview

A `partial` `[Factory]` class deriving from `List<T>` reached the other tier empty when the serialization format was Ordinal, which is the default. The generator treated the collection as an ordinary object and wrote its one public settable property, `List<T>.Capacity`, instead of its items. A collection now serializes as an array of its items in both formats.

## Bug Fixes

### A `partial` collection class carries its items in Ordinal format (#119)

The generator emits an ordinal converter for a `partial` `[Factory]` class with public settable properties and no constructor-injected services. That converter writes an object as an array of its property values. `List<T>` has one public settable property, `Capacity`, so a collection class such as

```csharp
[Factory]
internal partial class OrderLineList : List<OrderLine>, IOrderLineList
```

was written as `[capacity]`. A client that fetched the aggregate received an empty list, and a save sent the server an empty list. No exception was raised.

Collection types (any type implementing `IEnumerable`) no longer get the object-shaped converter. The list is a JSON array of its items in both formats, and each item takes that format's shape: in Ordinal, each `OrderLine` is itself an ordinal array.

**Who was affected:** plain RemoteFactory collection classes that are `partial`, have no constructor-injected services, and use the Ordinal format. Unaffected:
- non-`partial` collection classes, which already fell back to named JSON;
- collection classes with constructor-injected services, for which ordinal was already skipped;
- Neatoo lists, which derive from `ObservableCollection<T>`, have no public settable property, and are serialized by Neatoo's own converter.

The Design project's `OrderLineList` had this shape. Its tests checked lines only in Local mode, so the loss was not caught.

## What's New

Nothing new in the public API.

## Behaviour Notes

- **Only the items cross.** A collection class's own properties are not serialized, in either format. Named format never serialized them; Ordinal now matches it. State a list needs on the other tier, such as the items a user removed, belongs on an item or on the parent.

## Migration Guide

**None required.** Update the package and rebuild. Client and server must update together: a v1.10.2 client writes such a list as `[capacity]`, and a v1.10.3 server expects an array of items.

## Testing

- Generator: a `partial` `List<T>` class gets no ordinal converter; its item type still does.
- Integration, on the serializing client/server containers in Ordinal and Named: a fetched root's list arrives with its items; a save carries an item added on the client to the server. The Ordinal cases failed before the fix with an empty list; the Named cases passed.
- Design: an `Order` fetched through the Remote client arrives with its lines, in both formats.
- Publish-trimmed harness: absence checks and run pass.
- `Neatoo.RemoteFactory.sln`: 831 unit and 636 integration tests pass (5 skipped, all pre-existing), on net9.0 and net10.0. `Design.sln`: 106 tests pass on both.
