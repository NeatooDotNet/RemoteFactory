# v1.10.8 — A Client Disconnect No Longer Logs a 500

**Released:** 2026-10-16
**Breaking changes:** No. Update the server.

## Overview

One fix, in `Neatoo.RemoteFactory.AspNetCore`. When the browser abandoned a remote call, by a page reload, a navigation or a closed tab, the server recorded the request as an HTTP 500, and request logging wrote it at Error with a stack trace (#116). It now ends the request with 499, and nothing reaches the pipeline as an error.

## Bug Fixes

### A client disconnect was recorded as HTTP 500 at Error (#116)

`UseNeatoo()`'s endpoint gives the operation a token linked to `HttpContext.RequestAborted` and `IHostApplicationLifetime.ApplicationStopping`. When the client left, the `OperationCanceledException` escaped the endpoint. It came either from the operation's own cancelled work or from the check before the response is serialized, which fires even when the operation finished. ASP.NET Core then recorded a 500, and middleware that logs by status, such as Serilog's `UseSerilogRequestLogging()`, wrote it at Error with the stack trace. Every reload during an in-flight call looked like a server failure.

The endpoint now ends a cancelled request itself:

| Cause | Before | Now |
|---|---|---|
| The client left (`RequestAborted`) | 500, logged at Error | 499 (Client Closed Request), no body |
| The server is stopping (`ApplicationStopping`) | 500 | 503; the client's call throws `HttpRequestException` with `StatusCode` 503 |
| Any other `OperationCanceledException` (a timeout inside the operation) | 500 | 500, unchanged: it is the operation's own failure |

RemoteFactory's own `RemoteRequestCancelled` entry (event 7007) is still written at Information. A successful response is serialized as before.

Exposed: any server whose logging or alerting reads status codes. A host in the Development environment did not show it, because ASP.NET Core's developer exception page already answers an aborted request with 499.

## What's New

Nothing new for application code.

## Migration Guide

- **Update the server.** The fix is in `Neatoo.RemoteFactory.AspNetCore`; no rebuild of domain assemblies is needed. Client and server versions may differ: the wire format is unchanged from v1.10.7.
- **A shutdown during a call now answers 503, not 500.** Code that read `HttpRequestException.StatusCode` 500 as "the server is going down" now sees 503.

## Testing

- `EndpointCancellationTests` hosts `UseNeatoo()` in Production on TestServer, recording what request logging sees. It checks four cases: the client leaves after the operation finished, the client leaves during it, the server stops, and an operation's own cancellation. Without the fix, the first three fail.
- `Neatoo.RemoteFactory.sln`: 864 unit and 664 integration tests pass (5 skipped, all pre-existing), on net9.0 and net10.0. `Design.sln`: 175 tests pass on both (1 skipped as a known bug).
