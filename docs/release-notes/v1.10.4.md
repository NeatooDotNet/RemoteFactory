# v1.10.4 — An Interface-Factory Method Can Return `Task`

**Released:** 2026-10-12
**Breaking changes:** No.

## Overview

A method on a `[Factory]` interface declared to return non-generic `Task` generated code that did not compile. This is the defect v1.10.2 fixed for static `[Execute]` (#113), on the interface-factory leg: the generator wrapped the return type in `Task<>` a second time and the consumer's build failed inside the generated file with no NF diagnostic. It now generates a `Task` method and round-trips with no result.

## Bug Fixes

### Interface-factory method returning `Task` compiles and runs (#122)

```csharp
[Factory]
public interface IThingService
{
    Task Close(Guid id);
}
```

used to generate `public delegate Task<global::System.Threading.Tasks.Task> CloseDelegate(Guid id);` and fail:

```
error CS0738: 'ThingServiceFactory' does not implement interface member 'IThingService.Close(Guid)'.
'ThingServiceFactory.Close(Guid)' cannot implement 'IThingService.Close(Guid)' because it does not
have the matching return type of 'Task'.
error CS0266: Cannot implicitly convert type 'System.Threading.Tasks.Task' to
'System.Threading.Tasks.Task<System.Threading.Tasks.Task>'.
```

The return type is recorded fully qualified, so the renderer's check for an existing `Task` missed it. A `Task`-returning interface method now generates a `Task` delegate and factory method. Through the client proxy the call awaits the server method to completion, rethrows a server exception at the await, and reads no result. `[AuthorizeFactory<T>]` checks still run before the implementation, and a denial still throws `NotAuthorizedException`.

The defect was found earlier and recorded as deferred without an issue. The Design project worked around it with a `Task<bool>` method returning a sentinel `true`; that example now returns `Task` and throws when the item is missing.

## What's New

Nothing new in the public API. The generated client proxy uses `IMakeRemoteDelegateRequest.ForDelegateNoResult`, added in v1.10.2 in the `Neatoo.RemoteFactory.Internal` namespace.

## Behaviour Notes

- **Known, not fixed here:** on an interface factory with `[AuthorizeFactory<T>]`, an auth method whose parameter type some interface method lacks still generates a placeholder argument and fails CS7036 (#123). Keep every authorized method on the auth-matched parameter type until it is fixed.

## Migration Guide

**None required.** Update the package and rebuild. If you returned `Task<bool>` from an interface-factory method only because `Task` did not compile, you may change it to `Task`; client and server must update together, as for any change to a method's signature.

## Testing

- Generator: plain and authorized (async auth) interfaces with a `Task` method compile; the delegate and method are `Task` and call `ForDelegateNoResult`. These failed before the fix.
- Integration, on the serializing client/server containers: the call runs on the server; an async body completes before the await returns; a server exception reaches the client; a `Task<T>` method beside it still returns its value; with authorization, an allowed call runs and a denied one throws `NotAuthorizedException` without running. The integration project did not compile before the fix.
- Design: `IAuthorizedRepository.DeleteItem` returns `Task`; a new test deletes an item when allowed.
- Publish-trimmed harness: absence checks and run pass.
- `Neatoo.RemoteFactory.sln`: 834 unit and 642 integration tests pass (5 skipped, all pre-existing), on net9.0 and net10.0. `Design.sln`: 107 tests pass on both.
